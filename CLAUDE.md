# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Real-time voice-based Finnish language learning app. A phone app streams audio over WebSocket to a Rust server, which runs a voice pipeline: VAD → STT → LLM → TTS, and streams synthesized audio back.

## Architecture

- **server/** — Rust binary (axum + tokio) handling WebSocket connections and the full voice pipeline
- **app/** — Expo React Native mobile client with minimal UI (mic button + status)
- **infra/** — Terraform for Hetzner Cloud provisioning + deploy scripts
- **models/** — ONNX models for Silero VAD and Piper TTS (gitignored, downloaded via `models/download.sh`)
- **prompt.md** — LLM system prompt loaded at runtime, configurable without recompiling

## Networking

Server is publicly reachable at `wss://finnish.soikke.li/ws`. Caddy terminates TLS (automatic Let's Encrypt) and reverse-proxies to the Rust server, which binds `127.0.0.1:8080` only. Auth is a single shared secret (`AUTH_TOKEN` in server `.env`, generated by `deploy.sh --first-run`) sent by the app as an `Authorization: Bearer` header on WebSocket connect; the server does a constant-time compare before upgrading. `/health` is unauthenticated. The app gets the URL and token at build time via `EXPO_PUBLIC_SERVER_URL` / `EXPO_PUBLIC_AUTH_TOKEN` (`app/.env` locally, EAS env vars for TestFlight builds). WireGuard remains for SSH/admin use only — the app no longer uses it.

## Voice Pipeline

Audio in → Silero VAD (detect speech end) → Groq Whisper STT → Groq Llama 3.3 70B → Piper TTS → Audio out

The LLM wraps Finnish text in `[fi]...[/fi]` tags. The TTS module parses these to route English text to the English Piper voice and Finnish text to the Finnish Piper voice.

## Build & Run

```bash
# Download ONNX models (required first time)
./models/download.sh

# Build server
cd server && cargo build

# Run server (needs .env with GROQ_API_KEY and AUTH_TOKEN)
cd server && cargo run

# Local development (defaults to 127.0.0.1:8080)
AUTH_TOKEN=devtoken cargo run
```

## Key Dependencies

- **ort** = 2.0.0-rc.9 — ONNX Runtime (pinned to match silero-vad-rs)
- **ort-sys** = 2.0.0-rc.9 — must be pinned alongside ort to avoid TLS build errors in newer versions
- **ndarray** = 0.15 — must match silero-vad-rs (not 0.16)
- **piper-rs** — Rust bindings for Piper TTS
- **silero-vad-rs** — Rust bindings for Silero VAD
- **axum** — HTTP/WebSocket server
- **reqwest** — HTTP client for Groq API calls

## External Services

- **Groq API** (`api.groq.com/openai/v1`) — Whisper STT and Llama 3.3 70B chat completions
- **Hetzner Cloud** — CPX11 x86 server in Hillsboro, OR

## Deployment

Target: Hetzner CPX11 (x86_64). Deploy via `infra/deploy.sh` which uploads source and builds on the server (avoids cross-compilation issues with C dependencies like espeak-ng). It also installs Caddy and writes `/etc/caddy/Caddyfile` for the domain. First deploy with `--first-run` flag to install Rust/build tools, generate `AUTH_TOKEN`, set up WireGuard keys (admin only), and print the app config (`EXPO_PUBLIC_*` values). A DNS A record for the domain must point at the server before Caddy can obtain a certificate.

App distribution: EAS Build → TestFlight (`eas build --platform ios --profile production`, then `eas submit`). Family installs via a TestFlight external-group public invite link.
